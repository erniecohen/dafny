# Statement-bound variables in lambda captures

The lambda allocation introduction requires allocation of free captured values. A reference declared inside a proof block is bound there, so it cannot be a free capture of the enclosing lambda. Statement expressions collect their free variables separately, remove declarations and binders using resolved variable identities, and then contribute the remaining variables to the outer expression. An outer reference used in an initializer remains free, even when the initializer assigns a proof local with the same source name.

The repair changes only free-variable collection. It adds no allocation axiom and removes no premise for a genuine free value, receiver or captured heap. Assertion and calculation proof-local allocation controls verified before the allocation repair but failed with the initial capture collection: their allocation introductions required an unconstrained proof local outside its proof branch. The positive controls cover declarations, declaration patterns, match cases and binding guards. The negative controls retain rejection of a fresh reference captured from a later heap and retain an inhabited `ensures false` proof failure.

Labeled heaps are collected by the same scope rule: a label declared inside the statement is bound there, while a label outside the lambda remains a captured heap. The local-label positive checks allocation and evaluation. The outer-label negative separates the heap premise from the reference premise: its reference parameter is already allocated in the earlier heap, but the captured outer heap follows a new allocation. The earlier allocation assertion must still fail.

## Review evidence

The comparison uses pinned Z3 5.1.0 and the exact pre-change and composite compiler artifacts. The [pre-change statement probe](https://github.com/erniecohen/dafny/actions/runs/37261752625) verifies assertion-local and calculation-local controls in both resolvers and both additional-axiom settings. The [composite statement probe](https://github.com/erniecohen/dafny/actions/runs/37261681659) reports the allocation assertion error in all four settings for both controls. The [composite label probe](https://github.com/erniecohen/dafny/actions/runs/37262386459) fails the local-label control in all four settings, while the [pre-change label probe](https://github.com/erniecohen/dafny/actions/runs/37262680221) verifies it in all four settings. Both label probes verify the genuine outer-label positive. Diagnostic workflows record expected outcomes and exit successfully; their workflow status alone is not a correctness gate.

The [candidate compiler probe](https://github.com/erniecohen/dafny/actions/runs/37262633179) compiles the scope correction and preserves the original allocation regression outcomes in both resolvers and both additional-axiom settings: 19 verified / 0 errors for the positive input, 1 verified / 11 errors for the negative input, and 2 verified / 1 error for the original reproducer. That probe also exposed two fixture-only problems: an unbounded existential guard and a reserved identifier. The guard now explicitly ranges over `{c}`, and the identifier is `added`. These fixture corrections do not change product code.

The [corrected-fixture replay](https://github.com/erniecohen/dafny/actions/runs/37263041900) reuses that exact candidate compiler and pinned solver. All four resolver/option combinations verify the seven positive methods without warnings and report exactly three intended errors for the negative file: the later proof capture, the inhabited false contract, and the later outer heap capture. The replay also retains all original allocation regression outcomes listed above. The two new upstream-harness entries contain four explicit RUN commands apiece and share an oracle that records each resolver/option combination. The final rebased composite still requires the full fork gate before merge.
