# Statement-bound variables in lambda captures

The lambda allocation introduction requires allocation of free captured values. A reference declared inside a proof block is bound there, so it cannot be a free capture of the enclosing lambda. Statement expressions collect their free variables separately, remove declarations and binders using resolved variable identities, and then contribute the remaining variables to the outer expression. An outer reference used in an initializer remains free, even when the initializer assigns a proof local with the same source name.

The repair changes only free-variable collection. It adds no allocation axiom and removes no premise for a genuine free value, receiver or captured heap. Assertion and calculation proof-local allocation controls verified before the allocation repair but failed with the initial capture collection: their allocation introductions required an unconstrained proof local outside its proof branch. The positive controls cover declarations, declaration patterns, match cases and binding guards. The negative controls retain rejection of a fresh reference captured from a later heap and retain an inhabited `ensures false` proof failure.

Labeled heaps are collected by the same scope rule: a label declared inside the statement is bound there, while a label outside the lambda remains a captured heap. The local-label positive checks allocation and evaluation. The outer-label negative separates the heap premise from the reference premise: its reference parameter is already allocated in the earlier heap, but the captured outer heap follows a new allocation. The earlier allocation assertion must still fail.
