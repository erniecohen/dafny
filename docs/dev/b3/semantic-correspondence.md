## Capture and ownership

`Implementation` stores `StructuredStmts` and immediately constructs `Blocks` (lines 401-403). The conversion mutates labels, loop bodies and prefix metadata, and shares command lists, guards and invariants (conversion lines 80-113, 358-367, 417-446). Resolution/typechecking then traverse `Blocks` (implementation lines 569-588, 635-643).

A normal Boogie `Duplicator` does not isolate the structured representation: `StandardVisitor.VisitImplementation` visits locals, blocks, procedure and formals, without visiting `StructuredStmts` (lines 556-565); `Duplicator` inherits that behavior (lines 326-354). A B3 snapshot needs explicit ownership of structured nodes before the Boogie backend preprocesses the program. [Implementation](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/Core/AST/Implementation.cs), [conversion](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/Core/AST/StructuredBoogie/BigBlocksResolutionContext.cs), [visitor](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/Core/StandardVisitor.cs), [duplicator](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/Core/Duplicator.cs).

The census calls `Program.Resolve` and `Program.Typecheck` directly. `ExecutionEngine.GetVerificationTasks` also eliminates variables, coalesces/inlines/preprocesses, creates a VC generator and prepares implementations. It must not be called on the B3 route. [ExecutionEngine, lines 767-808](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/ExecutionEngine/ExecutionEngine.cs#L767).

## Raw-map equality

Dafny defaults to `TypeEncoding.Arguments` and pruning enabled (`DafnyOptions.cs`, lines 342-343). Boogie uses native SMT arrays only for monomorphic encoding with `useArrayAxioms=false` (`CommandLineOptions.cs`, lines 394,581). Its Arguments and Predicates map encodings use select/store equations without extensionality. Consequently, a bridge must preserve weak raw-map equality under the default path; adopting SMT arrays would strengthen that equality. Keep explicit Dafny collection-extensionality axioms independently. [Options](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/ExecutionEngine/CommandLineOptions.cs#L394), [Arguments equations, lines 253-262](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/VCExpr/TypeErasure/TypeErasureArguments.cs#L253), [Predicates equations, line 825](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/VCExpr/TypeErasure/TypeErasurePremisses.cs#L825).

## Contract and where schedules

- Entry: assume global where clauses, procedure in/out where clauses after formal substitution, implementation-local where clauses, then all checked and free requires. Output where clauses are also temporarily attached to implementation output variables for subsequent havoc. [Entry sequence, lines 668-708](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/VCGeneration/VerificationConditionGenerator.cs#L668), [parameter schedule, lines 359-429](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/VCGeneration/ConditionGeneration.cs#L359).
- Havoc: choose all fresh values first, then assume each changed variable's own where predicate using the entire updated environment and the correct old environment. An unchanged variable's where predicate is not re-assumed because another variable changes. Ordinary assignment adds no where assumption. `StateCmd` appends its local where clauses directly to the passive command list when entering the scope, without applying the current incarnation or old-frame substitutions. This is a different schedule from explicit havoc; current-value evaluation is not a valid replacement. [Havoc and state, lines 1243-1322](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/VCGeneration/ConditionGeneration.cs#L1243).
- Calls: the returned `StateCmd` has formal-substituted output where clauses attached to its temporary locals. Scope entry appends those raw predicates before the input assignments, without current-incarnation substitution. Consequently, mutable globals there denote raw symbols, rather than values established by preceding assignments. This follows from `CallCmd` lines 990-1005 and state entry in `ConditionGeneration` lines 1303-1319. The later joint havoc applies updated incarnations to those same where clauses, so its interpretation differs from scope entry. Then evaluate/save inputs; check nonfree requires unless the call itself is free; save modified globals; jointly havoc modified globals and temporary outputs with their where constraints; assume all ensures using call-relative old state; assign temporary outputs to actual outputs. Ordinary free requires are ignored at callers unless `:always_assume` or stratified inlining applies. [Call expansion, lines 750-1069](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/Core/AST/Commands/CallCmd.cs#L750).
- Callee exit: process ensures in declaration order. Check nonfree clauses; skip ordinary free clauses; assume free clauses carrying `:always_assume`. Thus a preceding always-assumed free clause can affect a later check. [Exit expansion, lines 80-109](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/VCGeneration/Transformations/DesugarReturns.cs#L80).

Source correspondence fixtures already exist: [Where](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Test/test2/Where.bpl), [AssumeEnsures](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Test/test2/AssumeEnsures.bpl), [FreeCall](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Test/test2/FreeCall.bpl). They were inspected for this audit, not executed as correspondence tests.

## Assertion learning

Default subsumption is `Always`. Per-assert `subsumption` overrides are 0 (never), 1 (unless the translated expression root is a quantifier), and 2 (always). When enabled, the continuation receives the assertion condition as a premise, while the assertion remains a separate obligation. Preserve this distinction with explicit checks and assumptions. [Wlp, lines 145-171 and 256-265](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/VCGeneration/Wlp.cs#L145).

## Visibility and pruning

Visibility starts with everything revealed. Prelude functions marked `AlwaysRevealed` ignore hide state. Named commands edit an offset set; wildcard commands reset its mode/set. Push copies the current state and pop restores the preceding state. Two Reveal-mode joins intersect hidden offsets; two Hide-mode joins union revealed offsets. A mixed-mode join returns the Reveal-mode operand unchanged; do not derive a replacement rule from the implementation's union comment. [RevealedAnalysis](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/VCGeneration/Prune/RevealedAnalysis.cs).

The pruner aggregates visibility poststates at every assertion in a split, then applies that one state to hideable function-to-axiom dependency edges. This is split-level declaration pruning, not dynamic per-command SMT enabling. With pruning disabled, the commands have no pruning effect. Initial slices must explicitly reject visibility forms they cannot preserve. [Pruner, lines 61-111](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/VCGeneration/Prune/Pruner.cs#L61).
