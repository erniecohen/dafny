# Issue 124: typed Boogie BV normalization proposal

This is a source-only implementation and English correspondence proposal. It does not implement normalization or establish a proof, runtime, or gate acceptance. It refines [the complete BV correspondence plan](native-bitvector-correspondence.md); the remaining wrapper, BV0, and rotation scope is still required. G3 context construction and runtime work are not accepted by this note.

The inspected Dafny/bridge source is [checkpoint f75f779770cd04ae9468e63efa7005a436383de2](https://github.com/erniecohen/dafny/tree/f75f779770cd04ae9468e63efa7005a436383de2). The pinned Boogie source is [73a0e214a87df85fc058270268c1d0706fd05bc9](https://github.com/erniecohen/boogie/tree/73a0e214a87df85fc058270268c1d0706fd05bc9). The checked language/protocol already represents the 17 primitives below, but the current normalizer does not yet translate BV types/literals/native functions. Its [TypeKey and expression dispatch](https://github.com/erniecohen/dafny/blob/f75f779770cd04ae9468e63efa7005a436383de2/Source/DafnyCore/Backends/B3/B3Normalizer.cs#L175) still need the reviewed extension.

## Exact sorts and the 17 primitive mappings

Write B(W) for the full SMT word sort of positive width W. Validate 1 <= W <= 4096 before allocating a power, numeral, or generated word AST. The complete normalized output must also satisfy the existing 4,194,304-bit aggregate, 100,000-node, depth-128, and 32-MiB limits. These are admission bounds with explicit failure, not assumptions added to a VC or machine-word semantics. Repeated expressions and the expansion of rotations count toward the output limits.

All table entries require their resolved operand types, formal types, result type, and call result type to agree. Unwind actual resolved type proxies and `TypeSynonymAnnotation.ExpandedType` with the depth bound; a declaration name is never a sort. Preserve width in structural map/UF keys. Return the canonical `#bvW` primitive spelling directly, without registering it as an opaque user type.

| And | B(W), B(W) -> B(W) | `bvand`; width W |
| Or | B(W), B(W) -> B(W) | `bvor`; width W |
| Xor | B(W), B(W) -> B(W) | `bvxor`; width W |
| Not | B(W) -> B(W) | `bvnot`; width W |

## Function identity, attributes, and actual Body precedence

For every declaration-based primitive route require a non-null resolved `FunctionCall.Func`, reference-identity membership of that Function in this source program's top-level declarations, zero type parameters, distinct ordered formal objects, one result, exact table arity/types, and a resolved empty type instantiation. The call's actual expressions must have the declared sorts. `FunctionCall.Func`, resolution, and signature checking are actual APIs at [FunctionCall.cs:14,101-164](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/Core/AST/Expression/FunctionCall.cs#L101); the function's printed name is not an identity key.

Read effective semantic attributes using the pinned priority: `bvbuiltin`, then `builtin` only if no valid string-valued bvbuiltin exists. [ExtractBuiltin:238-260](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/Provers/SMTLib/SMTLibLineariser.cs#L238) implements that rule; [QKeyValue.FindStringAttribute:193-202](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/Core/AST/QKeyValue.cs#L193) selects a one-string attribute. The proposed narrow recognizer conservatively rejects malformed or duplicate semantic attributes instead of guessing their intent. Parse the one allowlisted indexed spelling into bounded integer metadata and compare it to the actual result width. Never copy arbitrary attribute text into an SMT operator. Unknown claimed BV builtins remain explicitly Unsupported. Ordinary unannotated functions keep the existing UF/incompleteness policy.

Before interpreting an attribute, examine the **actual Function.Body**. [Boogie2VCExpr.TranslateFunctionCall/ApplyExpansion:1517-1588](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/VCExpr/Boogie2VCExpr.cs#L1517) substitutes actual arguments for the function's formal objects in Body and returns that expansion before builtin printing. Native-attribute recognition therefore initially requires Body==null. A separate bounded Body route may translate an exact literal, or an exact expression composed from table primitives and the actual formals. Require every formal reference's Decl to be the corresponding formal object, reject captures/cycles/other expression shapes, and recursively apply the same primitive checks. Do not substitute from detached DefinitionBody, DefinitionAxiom metadata, a name, or a positional guess. If Body exists but is outside the reviewed route, a native-looking attribute cannot override it.

The active-context rule is additional to program ownership. Builtins without Body do not derive their semantics from a revealable definition axiom; source function hide/reveal cannot turn their SMT builtin into an arbitrary UF. For every rewrite that uses a source axiom, however, exact membership/availability in the selected context is required. A program-level cache cannot certify a context-dependent rewrite for every check. G3 must supply and preserve this evidence; its proposed implementation is outside this note's acceptance.

## Canonical literals and the BV0 boundary

`BvConst(BigNum v,int b)` checks only nonnegative v at [AbsyExpr.cs:1081-1090](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/Core/AST/Expression/AbsyExpr.cs#L1081). The actual source solver printer emits exactly the lowest W bits at [SMTLibLineariser.VisitBvOp:879-901](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/Provers/SMTLib/SMTLibLineariser.cs#L879). Require literal Bits==the resolved positive source width, nonnegative Value, and the source numeral bound before canonicalization. For the existing 10,000-character source integer ceiling, reject a magnitude with bit length greater than 40,000 before decimal formatting, then apply the exact decimal-character bound; this coarse allocation guard admits every numeral within the original decimal limit because 10^D < 2^(4D). The BigNum already contains the exact integer; no host-width conversion or reparsing is needed. Canonicalize V modulo 2^W with bounded BigInteger arithmetic, then emit a canonical decimal BitvectorLiteral of at most 1,234 digits. V==2^W therefore becomes zero; silently rejecting all noncanonical source values would miss legitimate pinned source semantics. Negative values are rejected as malformed BvConst, while negative **IntToBitvector operands** remain legal. Direct external Raw/protocol word literals must already be canonical and are rejected if out of range; source canonicalization does not weaken their validation.

BV0 is a different source encoding: [DafnyPrelude.bpl:19](https://github.com/erniecohen/dafny/blob/f75f779770cd04ae9468e63efa7005a436383de2/Source/DafnyCore/DafnyPrelude.bpl#L19) is the Int alias, and [BplBvType/BplBvLiteralExpr:13-46](https://github.com/erniecohen/dafny/blob/f75f779770cd04ae9468e63efa7005a436383de2/Source/DafnyCore/Verifier/BoogieGenerator.BoogieFactory.cs#L13) use it and integer zero. Keep the resolved Int sort and existing variable identities. Never map an arbitrary integer variable to zero or create native B(0). A native `BvType` with Bits<=0 is unsupported, rather than inferred to be this alias.

The source where predicate for the actual alias is x==0 at [BoogieGenerator.cs:3935-3940](https://github.com/erniecohen/dafny/blob/f75f779770cd04ae9468e63efa7005a436383de2/Source/DafnyCore/Verifier/BoogieGenerator.cs#L3935). Retain the source's original where/havoc/check context under the existing normalization policy; conservatively omitted source constraints can enlarge target models, but must not be replaced by synthetic zero assumptions. The generator's width-zero function bodies are literal Int zero or literal Bool true/false, including comparisons, shifts/rotations, Int-to-BV0 and BV0-to-Int at [945-1058](https://github.com/erniecohen/dafny/blob/f75f779770cd04ae9468e63efa7005a436383de2/Source/DafnyCore/Verifier/BoogieGenerator.cs#L945). The exact Body-literal route can fold those source-owned monomorphic functions by their real body/type, without recognizing a BV0 name. Conversion to/from positive width already produces the explicit zeros/concat/extract shown above.

## The default BV2Int wrapper: exact owner and live axiom

`AddBitvectorNatConversionFunction(int w)` creates native N and ordinary F as separate actual Function objects, then emits a separate Axiom, not F.DefinitionAxiom, at [BoogieGenerator.cs:1035-1058](https://github.com/erniecohen/dafny/blob/f75f779770cd04ae9468e63efa7005a436383de2/Source/DafnyCore/Verifier/BoogieGenerator.cs#L1035). Its exact eligible shape is:

```text
forall b: B(W) :: { F(b) }
  ((0 <= F(b)) && (F(b) < 2^W)) && (F(b) == N(b))
```

Require all of the following, using resolved reference identities rather than names or structural equality that ignores triggers:

1. A is the actual top-level Axiom in this program and selected source context, A.CanHide==false, and A has no extra semantic metadata. Boogie's constructor defaults CanHide to false at [Absy.cs:544-558](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/Core/AST/Absy.cs#L544).
2. A.Expr is one unconditional ForallExpr, with zero type parameters, exactly one bound-variable object b of B(W), no WhereExpr, and no quantifier attributes. It is not an implication, existential, nested quantifier, or guarded definition. The producer overload supplies those empty fields at [AbsyQuant.cs:494-499](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/Core/AST/AbsyQuant.cs#L494).
3. Exactly one positive Trigger (Pos==true, Next==null), containing exactly the unary F(b) expression. Each IdentifierExpr.Decl is exactly b; each FunctionCall.Func is exactly F. No extra/missing/negative trigger term or declaration is admitted. [BplTrigger:880-881](https://github.com/erniecohen/dafny/blob/f75f779770cd04ae9468e63efa7005a436383de2/Source/DafnyCore/Verifier/BoogieGenerator.BoogieFactory.cs#L880) emits that trigger. Trigger.Pos/Tr/Next are explicit fields at [AbsyQuant.cs:330-363](https://github.com/erniecohen/boogie/blob/73a0e214a87df85fc058270268c1d0706fd05bc9/Source/Core/AST/AbsyQuant.cs#L330).
4. The body is exactly outer And(inner And(Le(0,F(b)),Lt(F(b),M)),Eq(F(b),N(b))), with resolved Bool/Int types and M exactly the bounded integer 2^W. All calls use precisely F or N and the same b identity; no captures, arithmetic reinterpretation, reordered or additional conjuncts, or type instantiations. The exact producer associates it this way at 1053-1057. Equality operand order is checked rather than inferred from names.
5. F and N are distinct, source-owned, monomorphic B(W)->Int functions with distinct actual formal/result identities. F has no Body or semantic builtin attribute. The initial wrapper route requires N.Body==null and N independently passes the exact native attribute/signature route for unsigned conversion; a native-looking name alone does not suffice. If N later has a recognized Body, that route must separately prove that the Body is exactly the unsigned conversion of its actual word formal; an arbitrary recognized Int-valued body such as zero is insufficient, and the attribute cannot override it. Detached metadata on either object cannot supply A.

Pinned Z3's `bv2int` spelling is unsigned: [z3-5.1.0 bv_decl_plugin.cpp:740-762](https://github.com/Z3Prover/z3/blob/z3-5.1.0/src/ast/bv_decl_plugin.cpp#L740) maps it to OP_UBV2INT, separately from OP_SBV2INT. The current [SMT-LIB theory](https://smt-lib.org/theories-FixedSizeBitVectors.shtml) uses other public conversion names; its mathematical signed helper named bv2int must not be confused with this pinned command spelling.

The demand-implies-live argument is exact. Do not synthesize the optional round-trip axiom or change `--additional-axioms`.

## Portable rotations are a conditional separate route

For already-converted x,y:B(W), let C be the B(W) literal W and r=UnsignedRemainder(y,C). Since 0<W<2^W, C is representable and nonzero. Let s=Subtract(C,r). Proposed lowering uses only the existing 17 operations:

```text
left(x,y)  = Or(ShiftLeft(x,r),        LogicalShiftRight(x,s))
right(x,y) = Or(LogicalShiftRight(x,r), ShiftLeft(x,s))
```

Use hygienic lets to retain x once and share r/s, charging all generated nodes/bindings. Unsigned r is in [0,W), so s has unsigned value W-r with no subtraction wrap. At r=0, s=W; the complementary ordinary shift gives zero and the other gives x. This proves the identity branch, including W=1. For 0<r<W, inspect each output bit: the low and high shifted regions are disjoint and reconstruct the input index modulo W in the requested direction. This is the universal mathematical proof plan for every positive width, every word, and every representable word count, including non-power-of-two widths and counts larger than machine integers.

Shifts themselves are never reduced modulo W: their count c is the unsigned value of the same-width word, and both give zero when c>=W. Implement native shift nodes rather than host powers 2^c. Non-power-of-two rotation cannot use count & (W-1). Source conversion of a count to B(W), including an original differently sized word count, must remain the exact emitted conversion tree.

The pinned Z3 declaration source confirms only the extended-rotate **signature**: [bv_decl_plugin.cpp:180-190,357-362](https://github.com/Z3Prover/z3/blob/z3-5.1.0/src/ast/bv_decl_plugin.cpp#L357) constructs two equal-width operands and a word result. It does not establish that every solver rewriting/decision path implements the modulo-W mathematical contract. Neither this source review nor a matching diagnostic pair establishes that missing equivalence. No ext_rotate attribute is mapped by this proposal until source-to-portable equivalence is separately reviewed for the pinned solver; unresolved rotation calls remain Unsupported with the complete rotation phase open. No default Boogie behavior is altered or bug asserted.

The actual Dafny rotation producer converts the argument to the result word width at [TrExprSpecialFunctionCall:1175-1185](https://github.com/erniecohen/dafny/blob/f75f779770cd04ae9468e63efa7005a436383de2/Source/DafnyCore/Verifier/BoogieGenerator.ExpressionTranslator.cs#L1175). Its original Int-count checks 0<=n<=W remain at [CheckWellformedSpecialFunction:1530-1536](https://github.com/erniecohen/dafny/blob/f75f779770cd04ae9468e63efa7005a436383de2/Source/DafnyCore/Verifier/BoogieGenerator.ExpressionWellformed.cs#L1530). Native total arithmetic never removes these checks. The same preservation applies to [DivisorNonZero:1049-1062](https://github.com/erniecohen/dafny/blob/f75f779770cd04ae9468e63efa7005a436383de2/Source/DafnyCore/Verifier/BoogieGenerator.ExpressionWellformed.cs#L1049) and [shift count checks:1064-1094](https://github.com/erniecohen/dafny/blob/f75f779770cd04ae9468e63efa7005a436383de2/Source/DafnyCore/Verifier/BoogieGenerator.ExpressionWellformed.cs#L1064). BV0 division's zero guard is unsatisfiable and must fail even when its actual constant result Body is folded.

## G1 model argument and proposed acceptance sequence

For every admitted positive width, use the bijection between the source native word carrier and the target native word carrier, indexed by the same W. Canonical low-bit literals, bitwise operations, modular arithmetic, unsigned comparisons/division/remainder, exact extract/concat, and integer conversions preserve values. Native division/remainder by zero use the same total primitive interpretation in both languages; existing source zero checks stay separate. No newly asserted nonzero premise is required. Closed UFs/maps retain their exact argument/result sorts; structural induction then preserves every supported expression's value. BV0 instead preserves the original Int interpretation and exact actual literal Body substitutions.

Exact Body substitution and the eligible **live** BV2Int equality preserve values by the source contracts above. Given the existing G1 command/check correspondence and a reviewed G3 selected source context, any source countermodel induces a target countermodel. Omitted assumptions/definitions enlarge the target model set; new primitive facts are not invented. Thus normalized validity implies the corresponding source validity. This is an English conditional model argument, not a mechanized theorem or a solver-soundness receipt. The placeholder RawAst Value=int/HasType=true semantics cannot be cited as such a theorem. Rotation enters the induction only after its separate source equivalence is established.

The smallest implementation checkpoint is positive-width sort/literal/extract/concat plus exact native declaration recognition for the 17 primitives, with greater comparisons reversed. Add the exact actual Body-literal BV0 route separately. Next add the source-owned wrapper only after its G3 availability contract is reviewed. Rotation is a final separate semantic checkpoint, not omitted scope. Candidate helper names such as TryNativeBitvector, TryBitvectorBody, and TryLiveUnsignedConversion describe proposed decomposition, not existing APIs. Keep source IDs, failed guard learning, traversal completion and aggregate result policy intact.

Acceptance must include meaningful controls for all signatures/widths, low-bit literals at/above 2^W, negative Int conversions, high-bit unsigned witnesses, extract/concat ordering and bounds, huge shift counts yielding zero, and exact Body precedence. Misleading names, wrong types/arity, detached declarations/axioms, incomplete binder identity, malformed attributes, captured bodies, guarded/wrong-range/extra-trigger/hideable wrapper axioms, and absent selected-context availability must not gain native recognition. Actual Dafny cases must retain conversion/count/divisor checks, BV0 negative guard failures, and triggered satisfiable `assert false` anti-vacuity failures. Per-context controls must forbid borrowing a wrapper axiom from a different mask. Future rotation controls must cover W=1, non-power-of-two widths, count 0/W/above W, and exact large representable counts, alongside the universal bit-index proof. Existing Int/Real/maps/default controls remain required. Fresh proof/build/runtime receipts and their actual denominators remain separate acceptance steps.
