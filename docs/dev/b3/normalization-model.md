# Initial conservative normalizer

[B3Normalizer](../../../Source/DafnyCore/Backends/B3/B3Normalizer.cs) consumes one already-resolved and typechecked Boogie implementation, reads its structured body, and produces owned protocol records. It neither creates an execution engine nor invokes VC generation, desugaring, passification, pruning, lambda lifting or solver code. It does not mutate either structured nodes or CFG nodes. Type proxies are followed through the pinned backing field because Boogie's public getter can shorten paths.

This is a conservative overapproximation, sufficient for useful bool/int assertions, assignments, conditionals, inductive loops and contracts in real Dafny translations. It is not complete prelude, heap, map, datatype, collection or lambda support. All source axioms, distinct-constant constraints and `StateCmd`/call-temporary scope-entry where predicates are omitted. Demanded nonidentity closed function instances become uninterpreted functions; constants become nullary functions; concrete nominal and raw-map types become opaque sorts. Direct reads of owned closed monomorphic store expressions use the [reviewed read-over-write ITE identity](map-helper-correspondence.md). No global ROW axioms are asserted; reads through variables or ordinary source functions retain uninterpreted signatures. Polymorphic map operations remain uninterpreted, and no extensionality equation is introduced. Lambda expressions become uninterpreted closure functions of their free current and old values. The result records every helper origin and the remaining approximation explicitly. Source axioms cannot make `assert false` provable in this slice.

## Direction of the semantic argument

Take any model and execution of the original typed Boogie unit. Interpret each demanded opaque sort by its original type's carrier and each closed function/map instance by its original interpretation. Interpret a lambda closure function by its original denotation as a function of the captured environment, including separate current and old global values. Every source state and expression then has a corresponding normalized state and expression. Omitted source constraints impose no additional condition on this interpretation. The monomorphic read/store ITE identity agrees with the source expression by the [source-model argument](map-helper-correspondence.md), using only forward primitive cast laws. Primitive bool/int operators retain their original semantics. A direct identity projection is rewritten only when an `AlwaysRevealed` function has an inline body or a universally quantified defining equality supplying that projection. The defining axiom must occur in the input program's top-level declarations, because detached metadata is not asserted by native checker setup. For a defining equality, the function call must instantiate every function type parameter bijectively with the quantifier's bound type parameters; an equality at a closed or restricted instance does not justify projection at other instances. The pinned visibility analysis cannot hide those definitions. Other bodies and defining equalities remain uninterpreted; an `:identity` attribute alone is insufficient. Dafny marks prelude functions `AlwaysRevealed`, so this rule retains literal identities.

Thus the normalized context admits the projection of every original execution. A universally successful check in that larger context is sufficient for its corresponding original check. A normalized counterexample need not extend to the omitted declarations or axioms: completeness and model reconstruction are deliberately not claimed. Dropping declarations is justified by this projection direction, rather than an unsupported claim that every reduced model extends to the full prelude. Future exact demand selection must supply the stronger correspondence argument and controls before restoring axioms.

## Explicit schedules

The schedules follow the [pinned source audit](semantic-correspondence.md):

- Entry snapshots demanded old globals before assumptions, then assumes global where clauses, substituted procedure input/output where clauses, local where clauses, and every free and checked requires clause.
- Parallel assignment saves all right-hand sides before writing targets. Assignment adds no where assumption. Havoc chooses every changed value jointly, then assumes only those variables' own where clauses with the entire updated environment. Scoped locals are fresh at scope entry. Their scope-entry where predicates are conservatively omitted: the pinned passifier appends these predicates raw, without substituting current incarnations. A subsequent explicit havoc still assumes its own where clauses with the updated environment.
- Calls start with fresh input/output temporaries and omit the raw scope-entry temporary-output where predicates. They then save all inputs, check ordinary nonfree requires unless the call is free, assume free requirements only with `always_assume`, jointly havoc modified globals and temporary outputs, assume every ensures clause, then copy outputs to actual targets. Ensures use call-relative old globals. Post-havoc temporary-output where predicates remain explicit. Requires and post-havoc temporary-output where expressions use the enclosing implementation's old globals: the pinned call expansion preserves their `old` expressions with `Substituter.Apply`; passification later replaces those using the enclosing old frame. Ensures instead use `ApplyReplacingOldExprs`, which eliminates `old` after substituting the saved modified globals. Ordinary parsed requires and procedure output-where clauses reject `old` during resolution because those contexts are single-state; a regression control records that boundary rather than admitting an invalid fixture.
- Every return checks nonfree ensures in declaration order, ignores ordinary free ensures and assumes `always_assume` free ensures in their declared positions. Explicit assertion checks carry separate learning flags for the global/default and per-assert subsumption policy.
- Loops use explicit initialization and preservation checks, header invariant assumptions, native loop havoc and lexical exit labels. The [control argument](loop-control-correspondence.md) states the inductive schedule and the exact restriction on header where clauses. Invariant obligations have distinct initialization/preservation roles in their IDs and descriptions.
- The static obligation manifest includes every normalized check, with its Dafny URI, line, column and failure description. Unsupported normalization returns no partial unit or obligation manifest.

## Initial boundary

The supported primitive operators are boolean connectives/equality, int addition/subtraction/multiplication/comparisons, and if-then-else expressions. Monomorphic quantifiers and simultaneous lets retain lexical binding; positive trigger groups are copied. Structured conditionals and nondeterministic choices are preserved, including the branch-assumption prefixes already present in Dafny's structured translation.

Backward/multiple-target/cross-region gotos, return expressions, free type parameters, polymorphic implementations/calls/quantifiers, wildcard/async calls, assumption-variable state, map assignment syntax, real/bitvector/float primitives, nontrivial coercions, division/modulo/power, hide/reveal commands and yield/action procedures fail closed. Division and modulo need a separate native-arithmetic correspondence review. The normalizer also rejects a called function with a direct primitive division/modulo/power body or defining equality: default Dafny arithmetic represents division as its prelude `Div` function, so this boundary applies to that actual translation rather than only hand-written binary expressions. Unknown unit/procedure/contract/command attributes are rejected. The generated `smt.arith.solver = 2` override is accepted; other per-unit solver overrides and inlining attributes are rejected. Pure visibility scope pushes/pops are ignored only after bounded inspection establishes the entire unit contains no hide/reveal command. Forward gotos are supported only when they exit a lexical prefix and resume at a later sibling or enclosing-list label; this covers the initial Dafny break/continue forms. Yield invariants, k-induction, unrolling, concurrent Houdini, irreducible graphs and CFGs larger than the audited bound fail closed. Lambda capture and constructed-IR traversals have explicit resource bounds. Solver budgets, logs, weights and triggers affect operational behavior; this document makes no performance-equivalence claim.

[DafnyB3Normalizer.Test](../../../Source/DafnyB3Normalizer.Test/NormalizerTests.cs) exercises real Dafny translation as well as the pinned contract/where/subsumption schedules. It can compile the current normalizer source against an exact-source compiler release with `DafnyNormalizerReferenceDirectory`, or project-reference DafnyCore normally. These normalization controls do not invoke a prover and do not establish backend verification verdicts. Worker/CLI verdict controls belong to the integration gate. The separate [map verdict runner](map-helper-correspondence.md#controls-and-executable-verdict-gate) provides an opt-in executable route for the exact positive, negative and omission controls; structural tests do not substitute for that route.

## Scope-entry where anti-vacuity boundary

The pinned passifier appends `StateCmd` local where predicates directly at entry, while explicit havoc substitutes the entire updated incarnation map. Evaluating both schedules against current values can strengthen the scope-entry context incorrectly. Consider this typed BPL shape:

```bpl
var g: int;
procedure Q() returns (x: int where g == 0); requires false;
procedure P(); requires g == 0; modifies g;
implementation P() { var x: int; g := 1; call x := Q(); }
```

The raw call-entry predicate `g == 0` refers to the initial symbol constrained by `P`'s requires clause, so it does not conceal the checked false precondition. The later havoc evaluates `g == 0` with the updated value and may make the continuation infeasible. Previously, evaluating the entry predicate with current `g == 1` made the precondition itself vacuous. The normalizer now drops this entry-only context and records the omission in `Approximations`. Dropping an original assumption enlarges the check context and preserves the normal-valid-implies-reference-valid direction. Post-havoc where constraints remain in their source positions. Exact raw-symbol scope correspondence is deferred.

The controls include this parsed BPL case and a manually constructed `StateCmd` with a resolved/typechecked predicate over a changed global, because the pinned AST has no surface syntax for `StateCmd`. These fixtures have been checked against source-level construction, resolution and typing rules; until executed, neither fixture acceptance nor either backend verdict is claimed as verifier evidence.

## Identity metadata boundary

The normalizer's typed-IR API must remain conservative even when a caller attaches a specialized axiom as a function's definition metadata. An axiom `forall x: int :: Identity(x) == x` for `Identity<T>(x: T): T` constrains only the integer instance. It cannot justify replacing `Identity(b)` by `b` at the Boolean instance. The defining-call guard therefore checks a bijection between all function type parameters and all quantified type parameters before permitting any projection. It also requires exact membership of the definition axiom in the input program's top-level declarations: the native prover setup asserts those declarations and does not assert a detached `Function.DefinitionAxiom` merely because a function references it. Closed and restricted definitions remain uninterpreted in this initial slice.

This API requirement is distinct from the reviewed source producer: the pinned parser's `Function.CreateDefinitionAxiom` quantifies a fresh copy of every function type parameter, and the reviewed Dafny definition-producing paths use that helper. Prelude literal identities retain their universal definitions and `AlwaysRevealed` eligibility. Direct `Function.Body` is a separate active route: the pinned native translator reads and substitutes any nonnull typed body before translating an uninterpreted function call, without inspecting an inline attribute. The normalizer additionally requires `AlwaysRevealed` for this route. Controls cover a manually attached integer-only identity axiom, a detached universal axiom, a direct typed body without an inline attribute, and universally parametric identities with one or two type parameters at integer and Boolean instances. Until executed, these controls provide source-review evidence only.
