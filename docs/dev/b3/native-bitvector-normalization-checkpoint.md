# Issue 124: positive-width normalization source checkpoint

This checkpoint implements the positive-width portion reviewed in the [typed Boogie correspondence proposal](native-bitvector-normalization-proposal.md). It is source-only: the new normalizer controls and actual-Dafny corpus have not been executed. The 62-batch [focused checked-language receipt](https://github.com/erniecohen/dafny/actions/runs/37224604457) verifies the selected Types, TypeChecker, and BitvectorResources contracts and all literal substring matches. It does not establish complete-library verification, a worker binary, or acceptance of these normalization changes.

`TypeKey` resolves the existing nonmutating proxy and alias routes, accepts native widths 1 through 4096, and returns the canonical `#bvW` primitive directly. Map and closed UF keys retain the width structurally. A native width zero is rejected; Dafny's actual `Bv0` Int alias remains Int. `CaptureBitvector` validates the resolved width and bounds the exact source magnitude before allocating a power or formatting its canonical word. It preserves the pinned Boogie low-W literal interpretation, including source magnitudes at or above 2^W. Direct schema literals still require canonical in-range values.

`BitvectorExtract` explicitly validates 0 <= Start < End <= operand width, with result width End-Start. `BitvectorConcat` preserves high E0 followed by low E1 and requires the exact bounded sum width. The normalizer emits the schema's closed typed operation metadata; it never forwards source attributes as SMT strings.

`TryNativeBitvectorFunction` requires the exact resolved Function object in the source top-level declarations, a monomorphic empty instantiation, distinct formal objects, no formal where clauses, and matching actual/formal/result sorts. For a Body-free declaration, `BitvectorBuiltin` checks the pinned bvbuiltin-before-builtin priority, conservatively rejects malformed or duplicate semantic attributes, and recognizes only the reviewed primitive spellings. Unsigned greater comparisons reverse the arguments. Shifts retain their same-width word counts, including counts greater than the word width. Integer-to-word conversion validates the exact canonical index and preserves every Int operand, including negative values.

The Body route runs before semantic-attribute interpretation, matching pinned Boogie's `ApplyExpansion`. `BitvectorBody` substitutes only references to the actual formal objects; it accepts literals, formals, identity coercions, extract/concat, and calls recursively justified by the same owned primitive/Body route. It rejects captures, cycles, unknown calls, and unreviewed expression shapes. A native-looking attribute cannot override an unaccepted actual Body. Detached DefinitionBody/DefinitionAxiom metadata supplies no premise. The separate Int-alias route preserves an exact actual Int/Bool literal Body with Int formals, independent of function names and attributes. This supports the emitted BV0 operations without replacing arbitrary Int state by zero.

The conditional model argument is structural. Choose for each source positive width the same full SMT word carrier as the target. Literal reduction, each native primitive, and extract/concat preserve the pinned source value at their checked sorts. Recursive actual-Body substitution preserves that value by the source translator's formal-substitution rule. The Int-alias route instead preserves the source's Int state, original constraints, and actual literal Body. Existing command/check correspondence then carries a source countermodel to a target countermodel; omitted axioms and ordinary UF definitions enlarge the target model set. Thus normalized validity implies source validity under the existing command/context correspondence and the reviewed primitive semantics. This is an English conditional argument, not a mechanized end-to-end theorem or a solver acceptance claim.

Width admission is explicit failure, not an added VC assumption. Expression/Body traversal uses the existing node/depth ceilings and an early aggregate word bound. `CheckOwnedBounds` separately counts the complete output, including repeated expression occurrences, function signatures, variable and binder declarations, and assignment/havoc targets. Its 4,194,304-bit bound matches protocol admission. Numeric output retains the existing message bound.

The typed controls check all 17 target primitive forms, greater-comparison reversal, resolved aliases, canonical low bits, maximum width, extract/concat ordering, huge same-width counts, negative primitive Int conversion, ownership, attributes, formal identity, Body precedence, captures/cycles, and aggregate boundaries. The actual-Dafny corpus adds native arithmetic/bitwise/comparison/shift/division/resize identities and separate failures for unsigned order, modular overflow, zero divisors, invalid counts, narrowing and negative conversion. BV0 has both a source-constraint positive case and a nonzero conversion failure. A satisfiable native-operation context retains `assert false` as a failure control.

The unannotated Dafny unsigned conversion wrapper remains an opaque function; this checkpoint neither consumes its equality axiom nor claims its range semantics. Exact per-context wrapper availability is a separate review gate. Native rotations are explicitly rejected; portable rotations remain a separate semantic and implementation checkpoint. No axioms, synthetic guards, inferred names, or default Boogie changes are introduced. The complete original scope remains open for these remaining routes, full checked-library and worker acceptance, lifecycle/default compatibility, and the wider backend gates.
