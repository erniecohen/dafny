# Proof-dependency sidecars for persistent module results

This extends the opt-in cache for [issue 261](https://github.com/erniecohen/dafny/issues/261), stacked on [ordinary text/TRX replay](https://github.com/erniecohen/dafny/pull/593), [ordinary JSON replay](https://github.com/erniecohen/dafny/pull/591), [resource-exhaustion replay](https://github.com/erniecohen/dafny/pull/589) and [CSV replay](https://github.com/erniecohen/dafny/pull/585).

Dependency-aware JSON/text, verification coverage and ordinary contradictory/redundant-assumption warnings can reuse complete module results under `--persistent-translation`. The stored inventory retains scope order, dependency order and reference identity. Scope inventories store the reporting projection: their name and potential set. Their `Decl` field is consumed only by the excluded refactoring/analysis paths and is not reconstructed; generated, datatype, by-method and export-copy declarations need no guessed AST identity. Each task still binds its declaration independently through the existing checked task symbol record. Each task retains its ordered covered membership and external compound dependencies. Equal descriptions or ranges do not identify the same dependency. Call-requires/ensures descriptions retain a structured reference to the related contract, whose range is formatted against the current source on load.

Each dependency records an admitted concrete kind, description, inclusive source range, reported excerpt, parsed source excerpt and warning facts computed by the existing warning predicates. Loading binds both endpoints to current source tokens and validates positions and the full parsed excerpt. Generated inclusive endpoint extents that differ from the parsed endpoint are unsupported and fall back, preserving coverage span lengths. The reported excerpt is retained separately because desugared calls can have generated token trivia; JSON preserves that fresh report text while coverage uses the current parsed tokens. Parsed tokens take precedence over generated copies at the same location. The entire inventory, every task declaration and every task membership must validate before a hit is returned. Missing fields, unsupported kinds, invalid indices, stale schemas, changed excerpts and unbindable locations miss and use the ordinary route. Older manifests lacking these optional sidecars remain readable for ordinary reports but cannot satisfy dependency reporting.

The restored manager supplies the same potential sets and covered identities to the existing report consumers. Replayed warning facts apply only to the admitted dependency kinds and retain the existing warning options, well-formedness exclusions, intentional contradictions, `assert false`, implicit assumptions and `assume true` exclusions. Coverage uses the original admitted kind for filtering and combining entries. No executable dependency or Boogie graph is reconstructed. The equality audit regenerates the complete inventory and membership and compares all their fields; times remain the only excluded result fields.

The regression compares independent solver, cache-off, cold, warm and audit runs, all non-timing JSON/text fields, normalized TRX reports, complete HTML coverage, diagnostics and every per-VC verdict/resource count/seed. Positive controls require real hits and no warm translation/preparation/solver work for supported modules. Negative controls retain a failing assertion, resource exhaustion, malformed and stale records; relocation changes both primary and included file names and ranges. Mutations exercise admission, membership, rebinding, related descriptions, warning facts, original-kind restoration and auditing.

Proof-refactoring suggestions and `--analyze-proofs` retain fresh preparation because they also consume pruned axiom and per-assert proof identities. Counterexample modules, finalized global/export projections and IDE lifecycle acceptance remain separate closure work. In particular, IDE consumers still require Boogie split and assertion details beyond these dependency sidecars; this change does not enable splitless tasks in the IDE. No option default, solver input, axiom or assumption changes.
