# Ordinary JSON reporting during persistent module replay

This extends the opt-in persistent module cache of [issue 261](https://github.com/erniecohen/dafny/issues/261), following [CSV replay](https://github.com/erniecohen/dafny/pull/585) and [resource-exhaustion replay](https://github.com/erniecohen/dafny/pull/589). Ordinary JSON previously forced every module through translation and preparation even when the task-result cache could replay its solver exchanges. The module manifest now supplies the additional assertion fields consumed by this report: filename, line, column and success description. JSON and CSV may be requested together. No new option or default behavior is introduced.

The manifest stores assertion positions relative to the innermost enclosing declaration, whose qualified name binds uniquely in the current program. Rebinding recovers the current filename and adds the current declaration's starting line. A position outside declarations uses the file's content label and requires a unique current file. Tokens outside the program retain literal fields when the graph fingerprint retains their coordinates. Boogie printing-buffer placeholders are unsupported because that fingerprint deliberately erases their unstable coordinates. The codec distinguishes basename, full path and URI spelling. Descriptions containing a source name are conservatively unsupported rather than rewritten. Capture failures leave optional metadata absent and preserve CSV recording; JSON requires a complete, current report for every scheduled task or the whole module misses. Assertion order and nullable report fields are preserved.

A new module-result schema and key domain reject older manifests. Every position field must be present, including a nullable literal filename; absent numeric fields are never interpreted as zero. Translation records and solver keys are unchanged. Existing current-graph, effective-option, outcome, limit and diagnostic checks continue to apply. Invalid outcomes and counterexamples still use the ordinary task path. Proof-dependency and coverage requests remain excluded: their dependency arrays require fresh preparation and are never approximated by these assertion records. Text and TRX retain their existing exclusions.

`--persistent-translation-audit` regenerates translation and prepared tasks and compares every stored assertion position and description, as well as the existing fields, excluding only measured duration. Report comparisons use independently populated uncached task results, retain every non-timing JSON field and all CSV verdicts/resource counts/seeds, and canonicalize scope/VC completion order. Runtime fields retain the existing replay marker contract.

The regression requires actual module hits and no warm solver starts, keeps a failing assertion and a resource-exhausted task, compares fresh/cold/warm/audit reports, moves and renames included sources, and composes module replay with checked resolution snapshots. It also checks changed effective limits, older/malformed records, missing assertion metadata, invalid anchors and filename kinds, coherent description tampering caught by the audit, and complete dependency-aware fallback. Unit tests exercise position bounds, unknown bindings, nullable fields, source-dependent prose and optional capture failures. Serial mutations of the report codec, eligibility, restoration, audit and logger selection must fail these controls.
