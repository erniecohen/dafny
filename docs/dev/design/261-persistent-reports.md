# Ordinary text and TRX reports during persistent module replay

This extends the opt-in persistent module cache for [issue 261](https://github.com/erniecohen/dafny/issues/261), following [CSV replay](https://github.com/erniecohen/dafny/pull/585), [resource-exhaustion replay](https://github.com/erniecohen/dafny/pull/589) and [ordinary JSON replay](https://github.com/erniecohen/dafny/pull/591). Text and TRX previously required fresh translation and preparation even when every solver exchange was cached. Both can now use complete module results under the existing `--persistent-translation` option. No option default, proof input or persistent schema changes.

Text consumes the same assertion filename, line, column and success description as JSON. Its replay path requires every scheduled task's complete portable assertion records, restores them against the current declarations and falls back for the whole module on missing or unbindable metadata. The logger reads the restored records without inspecting placeholder assertions or a missing Boogie split. Assertion ordering, batch numbering, seeds, outcomes and resource counts remain unchanged.

TRX uses the existing CSV test-result adapter, preserving its current scope names/source paths, outcomes, durations and properties. It needs no assertion metadata. The TRX serializer omits arbitrary `TestResult` properties, so setting the existing timing property alone does not identify replay in the XML. A reused test result now includes `Timing replayed: true` in `Output/StdOut`. Text prints the same marker after the duration of each reused batch and after the overall time of any scope containing a reused batch. These markers also apply to task-level solver replay when module replay is unavailable. Fresh results receive no marker; caching off retains the existing output.

CSV, JSON, text and TRX may be combined. JSON/text require the complete assertion records; CSV/TRX do not. Proof-dependency reporting, coverage, counterexample extraction, printing and other existing exclusions remain. Invalid or unsupported outcomes retain their ordinary path. The existing audit regenerates translation and preparation and checks the same complete stored records; no audit comparison is removed.

The regression compares independent fresh, cold, warm and audit runs, complete non-timing JSON/text/TRX reports and every per-VC CSV fact. It canonicalizes scope/VC completion order and TRX run identifiers, deployment names, execution identifiers and timestamp fields; deterministic source, test definitions, outcomes, diagnostics, assertion fields, dependency fields and summary counters remain in the comparison. Replayed time annotations are checked separately. Controls require actual module hits, no warm translation/preparation/solver work, independent text/TRX admission, a failing assertion and resource exhaustion, current locations after moving primary/included sources, malformed and stale records, audit-detected tampering and dependency-aware fallback. Text must miss for absent assertion records; TRX must still hit. Serial source mutations cover admission, text restoration and rendering, and each timing marker.

This completes ordinary verification logger support for the existing module-result fast path. Broader counterexample/dependency report replay, finalized global/export identities and persistent IDE lifecycle acceptance remain separate milestones. Stored Boogie text remains a record, never an input.

For the subsequent dependency-aware report, warning and coverage extension, see [proof-dependency sidecars](261-persistent-dependencies.md).
