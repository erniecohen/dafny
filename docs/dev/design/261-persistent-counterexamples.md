# Terminal counterexample reports in persistent module results

This extends the opt-in reporting work for [issue 261](https://github.com/erniecohen/dafny/issues/261), following [CSV](https://github.com/erniecohen/dafny/pull/585), [resource exhaustion](https://github.com/erniecohen/dafny/pull/589), [JSON](https://github.com/erniecohen/dafny/pull/591) and [text, TRX and proof-dependency reports](https://github.com/erniecohen/dafny/pull/593).

`--persistent-counterexamples` requires `--persistent-translation`. It admits resource-bounded Invalid tasks only when there is no time limit and every terminal diagnostic can be captured completely. The existing task-result cache still decides whether the solver interaction is reusable. The module manifest adds the exact counterexample count and detached verifier diagnostics: severity, error identifier, ordered message parts, main range and ordered related ranges/messages/identifiers. All packet fields must be present, including explicit null error identifiers. Error diagnostic counts must agree with the counterexample count. Every range carries both endpoints and the parsed source excerpt; restoration binds them to current source tokens and checks the excerpt. Prose containing source paths is conservatively rejected. A missing, stale, unsupported or incomplete packet prevents the whole-module hit.

A completed module task carries these diagnostics and its error count separately from its empty native counterexample array. Both CLI statistics and diagnostic reporting use those facts without a Boogie split. Assertion reports, proof-dependency membership and coverage remain subject to their existing completeness checks. No executable Counterexample or solver model is fabricated. With model extraction requested, successful and resource-exhausted modules can replay, but Invalid modules continue through translation, preparation and the task-result path. Timer-bounded errors, auxiliary timeout counterexamples and unsupported report locations remain conservative misses.

The equality audit regenerates results and compares every failure packet field, including related information. The regression checks independent fresh/cache-off/cold/warm/audit output, all per-VC resource facts and complete non-timing CSV/JSON/text/TRX/coverage reports; it also exercises error summaries, failed assertion/precondition/postcondition reports, relocation, graph replay, opt-out, model extraction, timer-bound fallback, coherent malformed records and deliberate oracle mismatches. Unit controls cover complete wire fields, range binding, diagnostic count and split-free reporting. Serial mutations exercise admission, recording, restoration, counters, diagnostic rendering and the equality oracle.

This is a terminal CLI reporting projection. Native model payloads, IDE assertion/model adapters and lifecycle acceptance, and finalized global identities remain separate obligations. The change adds no solver input, axiom or assumption and changes no option default.
