# Explicit run build filenames after option binding

Development already accepts the hidden `run --build` option. A nonempty `--boogie` binding calls the legacy option parser, which reapplies defaults and clears the compiled-output field. The selected build filename remains in the CLI option value. Restore that explicit value in the run handler after binding; leave the field unchanged when no build filename was supplied.

This is the alias-preservation portion of the already merged [PR #136](https://github.com/erniecohen/dafny/pull/136). It introduces no output option, project-output policy or verifier rule. The shipped handler already performs the corresponding restoration. Concurrent callers such as the compiler harness request separate output directories; discarding those requests creates shared source-adjacent projects. An intermittent historical missing-runtime failure is not established to have this cause.

Every compiler invocation and Main exits successfully and prints 42. Original development has exactly four output-location failures, all explicit build plus nonempty Boogie. The repaired compiler satisfies all 16 locations and the unchanged strict registered oracle (one selected harness case, zero failures). No-build controls preserve source-adjacent naming. These are compiler/runtime controls; verification is disabled, so they are not proof evidence.

The earlier [first comparison](https://github.com/erniecohen/dafny/actions/runs/37248673422) reproduces the two refreshed output failures and passes all eight refreshed repaired cases.
